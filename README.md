## Features

- **Kanban boards** — drag-and-drop task management (desktop & mobile) across To Do / In Progress / Done columns
- **Real-time collaboration** — live task updates via Supabase Realtime; changes from other users appear instantly without refresh
- **AI Summarise** — one-click project summary generated by LLaMA 3.1 via Groq
- **AI Prioritise** — AI-suggested priorities for all tasks with per-task reasoning; apply all in one click
- **Activity feed** — timestamped log of task creates, updates, deletes, and AI actions per project
- **Team invitations** — workspace owners can invite teammates by email; roles: OWNER / MEMBER
- **Assignee picker** — assign tasks to workspace members; avatars shown on task cards
- **Task editing** — inline modal: title, description, priority, status, due date, assignee
- **Overdue alerts** — red badge on the Projects sidebar link; overdue indicator on individual task cards
- **Multi-workspace** — users can belong to multiple workspaces; workspace switcher in sidebar
- **Dashboard analytics** — task status pie chart + per-project stacked bar chart (Recharts)
- **Google OAuth** — sign in with Google via NextAuth v5
- **Editable profile** — update display name from settings

## Local Development

### Prerequisites

- Node.js 20+
- A [Supabase](https://supabase.com) project
- A [Google Cloud](https://console.cloud.google.com) OAuth 2.0 client
- The [flowboard-ai](https://github.com/marinhomelissa65/flowboard-ai) service running locally (optional — AI buttons will gracefully fail without it)

### Setup

```bash
# 1. Clone and install
git clone https://github.com/marinhomelissa65/flowboard-web.git
cd flowboard-web
npm install

# 2. Copy and fill environment variables
cp .env.example .env.local

# 3. Push the schema to your Supabase database
npx prisma db push

# 4. Start the dev server
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Environment Variables

| Variable | Description |
|---|---|
| `DATABASE_URL` | Supabase connection pooler URL (port 6543) |
| `DIRECT_URL` | Supabase direct connection URL (port 5432) — used by Prisma migrations |
| `AUTH_SECRET` | Random secret for NextAuth — generate with `openssl rand -base64 32` |
| `NEXTAUTH_URL` | Full URL of your deployment, e.g. `https://flowboard-web-eight.vercel.app` |
| `GOOGLE_CLIENT_ID` | Google OAuth client ID |
| `GOOGLE_CLIENT_SECRET` | Google OAuth client secret |
| `NEXT_PUBLIC_SUPABASE_URL` | Your Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Supabase publishable (anon) key |
| `AI_SERVICE_URL` | Base URL of the flowboard-ai service, e.g. `https://your-service.onrender.com` |

## Database Scripts

```bash
npm run db:push      # Push schema changes to the database (no migration file)
npm run db:migrate   # Create and apply a named migration
npm run db:studio    # Open Prisma Studio (visual DB browser)
npm run db:generate  # Regenerate the Prisma client
```

## CI/CD

Every push to `main` triggers this pipeline via GitHub Actions:

```
Install → Prisma Generate → Test (Vitest) → Type-check → Lint → Build → Deploy (Vercel)
```

The **deploy** job only runs on `main` branch pushes and requires all prior steps to pass.

Required GitHub repository secrets:

```
DATABASE_URL · DIRECT_URL · AUTH_SECRET / NEXTAUTH_SECRET · NEXTAUTH_URL
GOOGLE_CLIENT_ID · GOOGLE_CLIENT_SECRET
NEXT_PUBLIC_SUPABASE_URL · NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY
AI_SERVICE_URL · VERCEL_TOKEN · VERCEL_ORG_ID · VERCEL_PROJECT_ID
```
